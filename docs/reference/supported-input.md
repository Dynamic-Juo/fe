# 지원하는 입력과 확인 시점

어떤 영상을 받아들이는지와, 각 조건을 어디서 언제 확인하는지 적는다. 조건마다 확인할 수 있는 위치가 달라 안내 시점도 달라진다.

## 받아들이는 입력

공개 상태이고 길이가 3분 이하인 YouTube 영상이다. 한국어 영상에 최적화되어 있으나 다른 언어도 거절하지 않는다.

**Shorts로 한정하지 않는다.** 이전 기준은 Shorts만 지원한다고 적었으나, 실제 구현은 프런트엔드와 서버 어디에서도 Shorts 여부를 확인하지 않는다. 길이 제한이 짧은 영상만 받는 목적을 이미 채운다. 근거는 [M-02](https://github.com/Dynamic-Juo/docs/blob/main/project/mvp-review.md)에 있다.

## 확인 단계

| 조건 | 확인하는 곳 | 시점 | 통과 못 하면 |
| --- | --- | --- | --- |
| 링크 형식과 영상 ID | 프런트엔드 | 입력 즉시 | 접수하지 않고 안내 |
| 영상 존재와 접근 가능 | 프런트엔드, YouTube oEmbed | 입력 즉시 | 접수하지 않고 안내 |
| 공개 상태, 연령 제한, 길이, 실시간 여부 | 서버, 다운로드 전 metadata | 접수 뒤 | 분석 실패로 표시 |
| 주 사용 언어 | 서버, 음성 인식 뒤 | 분석 중 | 거절하지 않고 안내만 덧붙임 |

접수 전에 거를 수 있는 것은 앞의 둘뿐이다. 나머지는 서버가 영상 정보를 받아본 뒤에야 알 수 있어 결과 화면에서 알린다.

## 프런트엔드가 보는 것

### 링크 형식

`domain/youtube.ts`의 `parseVideoId`가 11자 영상 ID를 뽑는다. 서버 파서와 같은 경계를 본다.

| 받는다 | 받지 않는다 |
| --- | --- |
| `youtube.com/watch?v=<id>` | 재생목록, 채널, 검색 주소 |
| `youtube.com/shorts/<id>` | YouTube가 아닌 주소 |
| `m.youtube.com/...` | 사용자 정보가 붙은 주소 |
| `youtu.be/<id>` | 기본이 아닌 포트 |

`/shorts/` 주소도 받지만 `watch?v=` 형태로 정규화해 서버에 보낸다. 두 주소가 같은 영상을 가리키므로 한 형태로 맞춰 보낸다. 시간 위치 같은 부가 정보는 버린다.

### 영상 존재와 접근 가능

`api/preview.ts`가 YouTube oEmbed로 제목, 채널명, 썸네일을 가져온다. 키가 필요 없고 브라우저에서 바로 부를 수 있다.

`401`, `403`, `404`만 접근 불가로 판정한다. 비공개, 삭제, 연령 제한 영상이 여기 해당한다. 네트워크 오류나 호출 제한으로 실패한 경우에는 막지 않는다. 그런 실패로 분석을 막으면 정상 영상까지 쓸 수 없게 된다.

oEmbed는 영상 길이를 주지 않는다. 길이 확인은 서버 몫이다.

## 서버가 보는 것

기준은 [API 계약](https://github.com/Dynamic-Juo/be/blob/main/docs/api-reference.md)이다.

다운로드 전에 metadata로 공개 상태, 연령 제한, 양의 길이, 기본 180초 상한, 실시간 여부를 확인한다. 여기서 걸리면 접수는 이미 끝난 뒤라 `job.error`로 돌아오고 화면에는 분석 실패로 나타난다.

주 사용 언어는 음성 인식을 마쳐야 알 수 있다. 한국어가 아니어도 분석을 중단하지 않고 판정 신뢰도가 떨어질 수 있다는 안내만 붙인다.

## 바꿀 때

지원 범위를 좁히려면 어디서 거를지 먼저 정해야 한다. oEmbed는 길이와 Shorts 여부를 주지 않으므로 프런트엔드에서는 확인할 방법이 없다. 서버가 metadata로 거르는 방식이 되며, 접수 뒤에 걸리므로 화면에서는 입력 안내가 아니라 분석 실패로 나타난다.

화면 문구는 `copy/strings.ts`의 `HOME.supportNotice`와 `ERROR.unsupportedUrlDetail`에 있다.
