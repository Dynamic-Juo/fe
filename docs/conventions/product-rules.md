# 제품 코드 기준

이 제품의 도메인에서만 성립하는 코드 규칙이다. 어느 프로젝트에나 적용하는 일반 기준은 [프런트엔드 코드 기준](code-style.md)에 있다.

여기 있는 규칙은 대부분 [Dynamic-Juo/docs](https://github.com/Dynamic-Juo/docs)에서 내린 결정이 코드에서 깨지지 않게 막는 장치다. 규칙을 바꾸려면 근거가 된 결정을 먼저 바꾼다.

## 도메인 용어를 코드에 그대로 쓴다

문서에서 쓰는 말과 코드에서 쓰는 말이 갈리면 대화할 때마다 번역이 필요하다.

| 문서 | 코드 |
| --- | --- |
| 주장 | `claim` |
| 검증 판정 | `verdict` |
| 처리 상태 | `status` |
| 근거 | `evidence` |
| 출처 | `source` |
| 발언 위치 | `spokenAt` |
| 미디어 조작 | `mediaManipulation` |
| 분석 작업 | `job` |
| 분석 ID | `analysisId` |

## 처리 상태와 검증 판정을 합치지 않는다

서로 다른 축이다. 한 값으로 합치면 대기 중인 주장에 판정이 붙는 상태를 표현할 수 있게 된다.

```
// 잘못됨. 대기 중과 근거 부족이 같은 자리에 온다
status: 'pending' | 'verifying' | 'completed' | 'supported' | 'insufficient'

// 올바름. 판정은 완료일 때만 존재한다
status: 'pending' | 'verifying' | 'completed' | 'failed' | 'timedOut'
verdict: 'supported' | 'refuted' | 'insufficient' | null
```

`verdict`가 `null`이면 판정 칩을 그리지 않는다. 회색 판정 칩도 두지 않는다. 사용자는 그것을 결과로 읽는다.

근거 부족은 검증이 끝나서 나온 판정이다. 그 주장의 처리 상태는 `completed`다. 실패가 아니다.

근거는 [U-03](https://github.com/Dynamic-Juo/docs/blob/main/project/mvp-review.md)이다.

## 조작이 없다고 단정하는 표현을 쓰지 않는다

미디어 조작 결과는 네 단계로 고정한다. 다른 문구를 만들지 않는다.

```
const MANIPULATION_LABEL = {
  suspected: '조작 의심',
  noSignal: '뚜렷한 조작 징후 없음',
  inconclusive: '판단 보류',
  unavailable: '분석 불가',
}
```

`조작되지 않음`, `실제 영상`, `진짜`, `안전함` 같은 표현을 쓰지 않는다. 탐지 모델이 지원하지 않는 조작이 있을 수 있어 없음을 단정할 수 없다.

라벨을 줄이지 않는다. `뚜렷한 조작 징후 없음`을 `징후 없음`으로 줄이면 단정에 가까워진다.

근거는 [U-04](https://github.com/Dynamic-Juo/docs/blob/main/project/mvp-review.md)다.

## 분석한 것과 업로더가 적은 것을 구분한다

미디어 조작 영역에는 얼굴 합성·변형을 두고, 업로더가 AI·합성 표기를 한 영상에만 표기 항목을 더한다. 앞은 우리가 영상을 분석한 결과이고, 뒤는 업로더가 제목이나 설명에 스스로 적어 둔 것을 읽은 값이다.

표기에는 조작 단계 라벨을 쓰지 않는다. `조작 의심`이라고 적으면 우리가 판정한 것처럼 읽힌다. `표기 있음`만 쓴다.

항목 이름과 설명에 `AI 생성`만 적지 않는다. 서버는 딥페이크·합성 영상·가상 인물·패러디도 같은 축으로 잡는다. 어떤 표기였는지는 근거 목록이 말한다.

**표기가 있을 때만 그린다.** 없다고 적으면 AI로 만들지 않았다는 뜻으로 읽힌다. 표기가 없는 것과 AI로 만들지 않은 것은 다르다.

영상 전체를 분석해 AI 생성 여부를 가리는 탐지는 MVP에서 제외한다. 음성 합성도 제외한다. 안 하는 분석은 항목을 만들어 두고 `분석 불가`로 표시하지 않는다. 항목이 있으면 분석했다가 실패한 것으로 읽히는데 실제로는 하지 않았다.

근거는 [T-06](https://github.com/Dynamic-Juo/docs/pull/7#discussion_r3991306606)이다.

## 조회 자격을 주소에 두지 않는다

분석 결과를 읽으려면 접수할 때 받은 토큰이 필요하다. 가진 사람은 그 결과를 볼 수 있다.

주소, 공유 링크, 로그, 분석 도구에 넣지 않는다. 결과 화면 주소는 작업 ID까지만 두고 토큰은 저장소에서 읽는다. 링크를 받은 사람이 남의 결과를 열 수 있으면 안 된다.

작업 ID로 토큰을 만들 수 없다. 서버가 접수할 때 서명해 주는 값이다. 토큰이 없는 기록은 복원하지 않고 지운다.

근거는 [공개 접수 연결](../reference/public-gateway.md)이다.

## 숫자 점수를 화면에 내보내지 않는다

판정 확률, 신뢰도 백분율, 위험도 점수를 표시하지 않는다. 보정 기준이 없어 실제 정확도로 오해된다.

서버 응답에 점수가 들어와도 화면으로 넘기지 않는다.

근거는 [U-03](https://github.com/Dynamic-Juo/docs/blob/main/project/mvp-review.md)이다.

## 두 분석을 하나로 합치지 않는다

미디어 조작 탐지와 주장 사실성 검증은 별개 결과다. 하나의 진위 판정이나 종합 점수로 합치지 않는다. 실제 영상에도 허위 주장이 있을 수 있고 합성된 영상의 발언이 사실일 수도 있다.

두 결과를 담는 자료 구조를 분리한다. 한쪽이 없어도 다른 쪽을 그릴 수 있어야 한다.

근거는 [M-01](https://github.com/Dynamic-Juo/docs/blob/main/project/mvp-review.md)이다.

## 주장 수가 확정되기 전에 숫자를 표시하지 않는다

주장 추출과 중복 병합이 끝나기 전에는 완료 개수도 전체 개수도 스켈레톤 카드 개수도 그리지 않는다. 나중에 숫자가 줄거나 늘면 신뢰를 깎는다.

전체 개수가 확정된 뒤에만 진행률을 계산한다. 진행률의 분모는 주장 수이며 미디어 조작 결과를 더하지 않는다.

## 완료 개수는 목록에서 센다

별도 상태로 두지 않는다. 같은 사실을 두 곳에 저장하면 언젠가 둘이 달라진다.

```
const completedCount = claims.filter(c => c.status === 'completed').length
```

## 폴링 응답이 화면 조작을 되돌리지 않게 한다

서버에서 온 값과 사용자가 화면에서 만든 값은 수명이 다르다. 카드를 펼친 상태, 스크롤 위치, 입력 중인 텍스트는 폴링 갱신에 영향받으면 안 된다.

두 상태를 한 객체에 담지 않는다. 주장 카드의 서버 자료와 펼침 여부를 같이 저장하면 갱신할 때마다 카드가 접힌다.

폴링은 최종 상태에 도달하면 멈춘다. `completed`, `completedWithLimitations`, `timedOut`, `failed` 넷이다.

## 주장 카드는 접어 둔다

카드는 처리 상태, 검증 판정, 주장 원문, 발언 위치까지만 펼쳐 두고 판정 근거와 출처는 접는다. 주장이 여덟 개인 영상에서 출처까지 모두 펴면 좁은 화면에서 화면이 너무 길어져 어떤 주장이 있었는지 훑을 수 없다.

펼침은 카드 안에서 일어난다. 상세 화면으로 옮기면 폴링으로 도착하는 나머지 카드를 놓친다.

보여줄 근거가 없으면 펼치기 자체를 만들지 않는다. 빈 칸을 펼치게 하면 누를 때마다 헛걸음이 된다.

와이어프레임은 이 항목을 제안으로 남겼고, 여기서 접힘을 기본으로 확정한다.

## 카드 순서를 재정렬하지 않는다

서버가 준 우선순위 순서를 유지한다. 완료된 것을 위로 올리지 않는다. 읽던 자리를 잃는다.

## 기술 오류를 사용자에게 보여주지 않는다

오류 코드, 스택 추적, 외부 서비스 이름을 화면에 쓰지 않는다. 무엇이 안 됐고 어디까지 영향받았는지를 적고, 추적은 분석 ID로 한다.

다시 시도할 수 있는 경우에만 다시 분석을 제공한다. 지원하지 않는 입력이나 검증할 주장 없음처럼 결과가 같을 일에는 강조하지 않는다.

## 부분 결과를 버리지 않는다

일부 분석이 실패해도 성공한 결과를 지우지 않는다. 화면을 비우고 오류만 남기지 않는다.

주 사용 언어가 한국어가 아닌 경우도 분석을 중단하지 않는다. 신뢰도가 떨어질 수 있다는 안내만 덧붙인다.

근거는 [R-10](https://github.com/Dynamic-Juo/docs/blob/main/project/prd.md)과 [U-05](https://github.com/Dynamic-Juo/docs/blob/main/project/mvp-review.md)다.

## 검토할 때 보는 것

- 도메인 용어를 그대로 썼는가
- 처리 상태와 검증 판정을 섞지 않았는가
- 미완료 카드에 판정 칩이 붙지 않는가
- 조작이 없다고 단정하는 표현이 없는가
- 분석한 결과와 업로더가 적은 표기를 구분했는가
- 안 하는 분석을 화면에 두지 않았는가
- 숫자 점수가 화면으로 새지 않는가
- 조회 자격이 주소나 로그에 남지 않는가
- 주장 수 확정 전에 개수를 그리지 않는가
- 폴링 갱신이 사용자의 화면 조작을 되돌리지 않는가
- 부분 결과를 지우지 않는가
