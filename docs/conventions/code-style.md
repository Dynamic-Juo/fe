# 프런트엔드 코드 기준

프레임워크와 제품에 관계없이 적용하는 코드 작성 기준이다. 이 제품의 도메인에서만 성립하는 규칙은 [제품 코드 기준](product-rules.md)에 있다. 스택을 정한 뒤에 생기는 폴더 구조, 상태 관리 도구와 빌드 설정은 별도로 다룬다.

기준을 어기는 편이 나은 경우가 있다. 그럴 때는 코드에 이유를 남긴다. 이유를 적을 수 없으면 기준을 따른다.

## 이름

이름은 무엇을 담는지가 아니라 무엇을 하는지를 드러낸다. `data`, `info`, `result`, `temp`, `handle`처럼 무엇이든 들어갈 수 있는 이름은 쓰지 않는다.

- 함수는 동사로, 값은 명사로 짓는다.
- 불리언은 `is`, `has`, `can`, `should` 중 하나로 시작한다.
- 반대 개념은 대칭으로 짓는다. `open`과 `close`, `add`와 `remove`를 섞어 쓰지 않는다.
- 이름에 타입을 넣지 않는다. `claimArray`가 아니라 `claims`다.
- 축약하지 않는다. `id`, `url`, `api`처럼 이미 굳은 것만 예외다.

이름이 길어지는 것은 문제가 아니다. 짧은 이름을 위해 의미를 버리지 않는다.

## 함수

함수 하나는 한 가지 일을 한다. 이름에 `그리고`를 넣어야 설명이 되면 나눌 때다.

인자가 셋을 넘으면 객체로 받는다. 호출부에서 순서를 외우게 하지 않는다.

중첩이 두 단을 넘으면 이른 반환으로 펼치거나 함수를 뺀다.

```
// 잘못됨
function submit(form) {
  if (form.isValid) {
    if (!form.isSubmitting) {
      if (form.url) {
        send(form)
      }
    }
  }
}

// 올바름
function submit(form) {
  if (!form.isValid) return
  if (form.isSubmitting) return
  if (!form.url) return
  send(form)
}
```

입력을 받아 출력을 내는 함수를 기본으로 삼는다. 바깥 값을 읽거나 고치는 함수는 테스트하기도 옮기기도 어렵다.

## 값

재할당보다 새 값을 만든다. 인자로 받은 배열이나 객체를 그 자리에서 고치지 않는다. 부르는 쪽이 모르는 사이에 값이 바뀐다.

```
// 잘못됨
function sortByTime(claims) {
  return claims.sort((a, b) => a.startedAt - b.startedAt)
}

// 올바름
function sortByTime(claims) {
  return [...claims].sort((a, b) => a.startedAt - b.startedAt)
}
```

의미를 가진 숫자와 문자열에는 이름을 붙인다. 같은 값이 두 곳에 나타나면 상수로 뺀다.

## 타입

`any`를 쓰지 않는다. 모르는 값은 `unknown`으로 받고 좁혀서 쓴다.

타입 단언보다 좁히기를 쓴다. `as`는 컴파일러를 속이는 것이지 값을 보장하지 않는다.

없을 수 있는 값만 선택적으로 만든다. 전부 선택적인 타입은 아무것도 보장하지 않는다.

정해진 값의 집합은 문자열 리터럴 유니온으로 적는다. 값이 그대로 보여서 읽기 쉽고, 빠뜨린 분기를 컴파일러가 잡는다.

## 조건 분기

값이 셋 이상이면 조건문 대신 대응표를 쓴다. 값이 늘어날 때 고칠 자리가 한 곳으로 모인다.

```
// 잘못됨
if (kind === 'news') label = '언론 보도'
else if (kind === 'official') label = '정부 · 공공기관'
else label = '기타'

// 올바름
const SOURCE_LABEL = {
  news: '언론 보도',
  official: '정부 · 공공기관',
  etc: '기타',
}
```

삼항 연산자를 겹쳐 쓰지 않는다. 한 단계까지만 쓴다.

## 비동기와 에러

비동기 작업에는 진행 중, 성공, 실패 세 상태가 있다. 셋을 모두 다룬다. 실패를 빠뜨린 화면은 아무것도 없는 화면이 된다.

실패를 삼키지 않는다. `catch`에서 할 일이 없으면 감싸지 않는다.

```
// 잘못됨
try { await analyze(url) } catch (e) {}
```

에러를 삼킨 자리는 나중에 원인을 찾을 수 없다.

요청에는 취소 수단과 시간 제한을 둔다. 같은 요청이 겹쳐 나가지 않게 막는다.

## 부수효과

부수효과는 언제 실행되고 언제 멈추는지가 코드에서 보여야 한다. 타이머, 구독, 감시자는 시작한 자리에서 정리한다.

정리를 빠뜨리면 화면을 떠난 뒤에도 계속 돈다. 요청이 남고 메모리가 쌓인다.

## 컴포넌트 경계

한 컴포넌트는 한 가지를 그린다. 데이터를 가져오는 일과 그리는 일을 한 컴포넌트에 넣지 않는다. 그려야 할 모양을 시험하려면 데이터까지 준비해야 한다.

값을 세 단계 넘게 내려보내고 있으면 구조를 다시 본다. 중간 컴포넌트가 쓰지도 않는 값을 받아 넘기고 있다는 뜻이다.

한 파일에서 외부로 내보내는 컴포넌트는 하나로 한다.

목록에는 안정적인 키를 준다. 배열 순서를 키로 쓰면 항목이 끼어들 때 엉뚱한 자리가 다시 그려진다.

## CSS

전역 선택자로 요소를 잡지 않는다. 범위가 파일 밖으로 새지 않게 한다.

`!important`를 쓰지 않는다. 이겨야 할 규칙이 있으면 그 규칙을 고친다.

`z-index`를 필요할 때마다 큰 숫자로 올리지 않는다. 단계를 정해두고 그 안에서 쓴다.

간격과 크기는 정해둔 값에서 고른다. 임의의 픽셀을 그때그때 적지 않는다.

이미지에는 크기를 지정한다. 불러오는 동안 아래 내용이 밀려 내려가지 않는다.

## 접근성

누를 수 있는 것은 누를 수 있게 생긴 요소로 만든다. `div`에 클릭 처리를 붙이면 키보드로 닿지 않고 화면 낭독기가 읽지 못한다.

의미를 가진 요소를 쓴다. 제목은 제목 요소로, 목록은 목록 요소로 적는다.

색만으로 정보를 전달하지 않는다. 색을 지워도 읽을 수 있어야 한다.

입력에는 설명을 연결한다. 자리 표시자를 설명 대신 쓰지 않는다. 입력을 시작하면 사라진다.

포커스가 어디 있는지 보이게 한다. 기본 표시를 지우면 대신할 것을 둔다.

## 주석

무엇을 하는지는 코드가 말한다. 주석에는 왜 그렇게 했는지를 적는다.

기준을 벗어난 곳, 외부 서비스의 제약을 우회한 곳, 나중에 바뀔 것을 아는 곳에 남긴다.

주석이 코드를 설명하고 있으면 코드를 고친다.

## 남기지 않는 것

주석으로 막아 둔 코드를 남기지 않는다. 되돌릴 일이 있으면 git에서 찾는다.

쓰지 않는 함수, 변수와 파일을 지운다. 지우기 아까우면 지운다.

## 미리 만들지 않는다

쓰이지 않는 추상화를 만들지 않는다. 같은 코드가 세 번째 나타날 때 공통으로 올린다.

두 곳이 비슷해 보인다는 이유로 합치면, 한쪽만 바뀌어야 할 때 갈라내는 비용이 더 든다.

한 줄로 되는 일에 패키지를 가져오지 않는다. 번들 크기와 유지보수 위험이 함께 온다.
